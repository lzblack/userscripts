# 本地测试和更新到 GreasyFork 指南

## 本地测试步骤

### 方法一：在 Tampermonkey 中直接编辑（最简单）

1. **打开 Tampermonkey 管理面板**
   - Firefox: 点击扩展图标 → 管理面板
   - Chrome/Edge: 点击扩展图标 → 管理面板

2. **找到你的脚本并编辑**
   - 在脚本列表中点击"豆瓣书名号转搜索链接"
   - 点击"编辑"按钮

3. **复制本地文件内容**
   - 打开 `douban-title-mark-search.user.js`
   - 全选复制（Ctrl+A, Ctrl+C）

4. **粘贴到 Tampermonkey 编辑器**
   - 在 Tampermonkey 编辑器中全选（Ctrl+A）
   - 粘贴（Ctrl+V）
   - 点击"文件" → "保存"（或 Ctrl+S）

5. **测试**
   - 打开或刷新豆瓣网站（如 https://movie.douban.com/subject/1234567/）
   - 检查书名号是否转换为链接
   - 测试展开长评论功能

### 方法二：使用本地文件同步（适合频繁修改）

1. **在 Tampermonkey 中创建脚本**
   - 新建脚本，设置基本元数据

2. **每次修改后**
   - 复制本地文件内容
   - 粘贴到 Tampermonkey 编辑器
   - 保存并测试

### 测试检查清单

- [ ] 页面加载时，书名号自动转换为链接
- [ ] 点击书名号内的文字可以跳转到搜索页面
- [ ] 展开长评论后，新展开的内容中的书名号也转换为链接
- [ ] 页面滚动加载新内容时，书名号自动转换
- [ ] 没有页面卡顿现象
- [ ] 书名号本身不是链接，只有内容是可点击的

## 更新到 GreasyFork

### 步骤 1: 更新版本号

每次更新前，记得修改脚本中的版本号：

```javascript
// @version      1.2  // 改为新版本号，如 1.3
```

版本号格式建议：
- 小修复：1.2 → 1.2.1
- 新功能：1.2 → 1.3
- 重大更新：1.2 → 2.0

### 步骤 2: 更新 CHANGELOG.md 并准备更新说明

1. **更新 CHANGELOG.md**
   - 打开 `CHANGELOG.md` 文件
   - 将 `[Unreleased]` 部分的变更移到新版本号下
   - 添加发布日期
   - 参考 `CHANGELOG_GUIDE.md` 了解格式规范

2. **准备 GreasyFork 更新说明**
   
   在 GreasyFork 更新时，从 `CHANGELOG.md` 中提取对应版本的更新内容，格式如下：

   ```
   版本 1.2 更新内容：
   
   - 修复长评论展开后书名号链接失效的问题
   - 优化性能，减少不必要的检查
   - 改进动态内容检测机制
   ```

   或者直接复制 CHANGELOG.md 中对应版本的内容。

### 步骤 3: 在 GreasyFork 上更新

1. **登录 GreasyFork**
   - 访问 https://greasyfork.org/
   - 登录你的账号

2. **进入脚本管理页面**
   - 点击右上角头像 → "我的脚本"
   - 找到"豆瓣书名号转搜索链接"

3. **点击"更新脚本"**
   - 点击脚本页面上的"更新脚本"按钮

4. **粘贴新代码**
   - 打开本地 `douban-title-mark-search.user.js` 文件
   - 全选复制（Ctrl+A, Ctrl+C）
   - 粘贴到 GreasyFork 的代码编辑器中

5. **填写更新说明**
   - 在"更新说明"框中填写本次更新的内容
   - 可以参考上面的格式

6. **提交更新**
   - 检查代码无误后，点击"更新脚本"按钮
   - GreasyFork 会自动验证脚本格式

### 步骤 4: 验证更新

1. **等待审核**（如果是新脚本或重大更新）
   - GreasyFork 可能需要几分钟审核

2. **检查脚本页面**
   - 确认版本号已更新
   - 确认更新说明已显示

3. **用户自动更新**
   - 安装了脚本的用户会在下次打开 Tampermonkey 时看到更新提示
   - 他们可以选择自动更新或手动更新

## 开发工作流建议

1. **本地开发**
   ```
   修改代码 → 在 Tampermonkey 中测试 → 发现问题 → 修改代码 → 测试
   ```

2. **版本控制**
   - 使用 Git 管理代码
   - 每次更新前提交代码
   - 写好 commit message

3. **测试充分后再发布**
   - 在不同页面测试（电影页、书籍页、评论页等）
   - 测试各种场景（展开评论、滚动加载等）
   - 确认没有性能问题

4. **更新到 GreasyFork**
   - 更新版本号
   - 写好更新说明
   - 提交更新

## 常见问题

**Q: 如何快速测试修改？**
A: 使用 Tampermonkey 的编辑功能，修改后保存，刷新页面即可看到效果。

**Q: 更新后用户多久能看到？**
A: 用户打开 Tampermonkey 时会自动检查更新，通常立即就能看到。

**Q: 如何回退版本？**
A: 在 GreasyFork 脚本管理页面可以查看历史版本，可以恢复到之前的版本。

**Q: 更新说明是必须的吗？**
A: 虽然不是必须的，但强烈建议填写，让用户了解更新内容。
