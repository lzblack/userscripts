# 豆瓣一键添游戏 | One-Click Add Game to Douban

在 Steam 商店页查豆瓣是否已收录该游戏；未收录则一键跳转豆瓣「创建游戏条目」、自动回填全部可填字段并注入封面。人工只审核和提交，绝不自动提交任何表单。

与 [`douban-add-book/`](../douban-add-book/)（Amazon → 豆瓣图书）同构，payload 是两侧之间的契约，豆瓣侧与来源无关。

## 状态

两侧都已实现。豆瓣建条目页在登录墙后、真实 HTML 未取到，所以回填器写成**不依赖表单结构**的形式（见下），并自带诊断——认不出字段时只报告、不乱填。等真跑过一次再定版。

## 使用流程

1. 打开 Steam 商店页（`store.steampowered.com/app/…`），标题下方角标显示豆瓣查重结果：
   - **已收录** → 条目链接 + 评分，流程结束。
   - **名字相近** → 列出相近条目让你先排除，再决定是否仍要添加。
   - **没搜到** → 「+ 添加到豆瓣」按钮。
   - **查重失败**（风控/网络）→ 降级为手动搜索链接，不假装「没有」。

   角标默认只有一行（约 45px 高），配色取自 Steam 自己的面板，不抢版面；点「详情」才展开字段表、告警和「创建后需手动补」清单。相近条目属于决策依据，常驻在首行、不折叠。

2. 点「添加到豆瓣」→ 新标签打开 `www.douban.com/game/create?thing_name=…`。第一步是豆瓣自己的查重（「以上都不是，继续创建」），第二步「详细资料」才是表单，脚本在那里回填，你核对后提交。

   建条目页只收 名称 / 中文名称 / 平台 / 类型 / 发售时间 / 简介 / 图标——**开发商、发行商、官方网站没有对应字段**，脚本会把抓到的值列出来，条目建成后到条目编辑页补。

## 设计要点

- **不刮 Steam 的 DOM**，全部走官方 `store.steampowered.com/api/appdetails`。因此页面改版不影响，成人内容年龄门也不需要特判。
- **拉两份响应**：`l=schinese` 给中文名与中文简介，`l=english` 只为拿可解析的发行日期——中文那份返回的是「2020 年 9 月 17 日」。
- **类型按 genre id 映射**，不按文案：id 跨语言稳定，description 会变。映射目标是**建条目页那 19 个类型的名字**——`/game/explore` 筛选器上只有 15 个（少了卡牌 / 大型多人在线 / 光枪射击 / 文字冒险），那套 id 对建条目页不作数，所以回填按标签文本匹配复选框、不认 id。Steam 的「独立 / 休闲 / 免费开玩 / 抢先体验」在豆瓣无处可落，进告警让人工补，不猜。
- **平台只填 Steam 能确知的三个**（PC / Mac / Linux），主机平台留空。
- **查重没有主键**。图书有 ISBN，`/isbn/404` 是硬证据；游戏只能按名字搜 `www.douban.com/search?cat=3114`，所以「没搜到」只作弱信号呈现，措辞是「没搜到」而非「未收录」。中英名各搜一次后合并判定。
- **中文名拿不到就留空**，不臆造翻译（Steam 没有中文商店名时 `l=schinese` 返回的仍是英文名）。
- **回填不依赖表单结构**。豆瓣建条目页的 HTML 没到手，所以不写 `.item > label` 这类选择器，而是把表单线性化成 token 流、按「最近的前驱字段标签」给控件归组——table / div / dl 任何排版都成立。只有 `FIELD` 表里的标签会开新组，提示语、复选框自带的「PC」「动作」、日期后的「年/月/日」都只是过路 token。这一层有单测。
- **封面先于字段**。豆瓣收到图标后会把整个表单区重绘一遍，先填字段的话会被冲掉（而横幅在表单外面不受影响，于是出现「横幅说已填、表单却是空的」）。所以顺序是：注入封面 → 等 DOM 安静 → **重新扫一遍表单**（旧元素引用已作废）→ 回填。
- **认不出就报告，不乱填**。一个字段都没匹配上时只出一条诊断横幅（列出认出/没认出的字段），不动表单、不消费数据。逐字段也一样，而且「已填」**以读回 DOM 为准**——写过不等于填上了，填了又被冲掉的会进「没填上」并重试一轮。
- **风控不冒充「没搜到」**。豆瓣搜索连续请求会整页 403，且它的风控页也可能回 200，所以除了看状态码，还要求响应带着搜索页自己的结构标记，缺了就报「查重失败」转人工搜索。英文名命中就不再查中文名，常见路径只花一次请求。
- **绝不自动提交**：每一步都由你确认。
- 跨标签数据走本地存储传递，10 分钟过期、消费即删。

**⑦ 豆瓣侧回填**

→ 若看到「**没认出这一步的表单**」或「没找到控件」，把那两行列出的字段名发我就行——改一张 `FIELD` 表即可，不用重写选择器。

**核对字段时重点看**：中文名是否合豆瓣习惯、发售时间、类型映射与未映射告警、平台、简介是否干净（不该出现「数字豪华版」「Join Our Community!」这类版本/社群样板）、封面是否是竖版。

> 豆瓣建条目页的真实 HTML 未取到，回填器是按「不依赖表单结构」写的，并在一个排版刻意不同的模拟表单上验过。第一次真跑请留意横幅的诊断信息。

## 开发

纯函数层（appid 解析、HTML 转文本、类型/平台映射、标题匹配、查重判定、回填计划）有 `node --test` 单测：

```sh
node --test douban-add-game.test.js
```

`fixture-search.html` 截自真实的 `?cat=3114` 搜索结果页（匿名可取），覆盖精确命中、同系列续作、含 HTML 实体且无评分三种形态。

豆瓣建条目流程的实测结果（两步共用同一个 URL `https://www.douban.com/game/create`，只能靠页面内容分辨）：

| 步骤 | 内容 | 脚本行为 |
|---|---|---|
| 1. 基本资料 | 只有名字 + 豆瓣自己的查重结果，底下「以上都不是，继续创建」 | 只出提示横幅，**绝不代点**那个按钮 |
| 2. 详细资料 | 名称 / 中文名称 / 平台 / 类型 / 发售时间 / 简介 / 图标 | 全部回填 + 注入封面，停在提交前 |
| 3. 创建完成 | — | 不介入 |

无构建步骤，单文件 IIFE；纯函数与运行期共用同一文件，靠 `module.exports` 守卫区分 node 与浏览器。

## 权限与隐私

- `@match` 仅 `store.steampowered.com/app/*` 与 `www.douban.com/game/create*`。成人内容游戏会先跳到 `/agecheck/app/…`，那一页不在匹配范围内，过了年龄门再看角标。
- `@connect store.steampowered.com`：读官方 appdetails 接口。
- `@connect www.douban.com`：用你的登录态搜索该游戏是否已收录（只读，不做任何写操作）。
- `@connect shared.akamai.steamstatic.com`：抓取封面图。
- 不上传任何数据、不接入第三方或分析服务。
